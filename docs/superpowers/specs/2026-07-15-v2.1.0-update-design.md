## Section 2: Dead Code Removal

### `includes/data-eraser.php`
- Remove `anonymize_user_data()` (lines 251–276).
  - Was an old approach where users stayed in `wp_users` with anonymized data.
  - Never called in the current system; WooCommerce order anonymization is handled by `anonymize_woocommerce_orders()` which IS called correctly in `handle_woocommerce_data()`.

### `includes/admin-settings.php`
- Remove `add_user_list_styles()` method and its `admin_footer-users.php` hook from the constructor.
  - Method body is empty; archived users are not in `wp_users` so nothing to style.
- Remove `modify_deleted_user_actions()` method and its `user_row_actions` hook from the constructor.
  - Attempted to modify row actions for archived users in the Users list. Never fires because archived users are removed from `wp_users` and do not appear in the list.

### `user-self-delete.php` (main)
- Remove `require_password`, `deletion_cooldown`, `cooldown_period` keys from `activate()` defaults array.
  - These settings were never implemented (no UI, no logic using them).

### `includes/user-self-delete.php`
- Remove `prevent_deleted_user_login()` method and its `wp_authenticate_user` hook.
  - `wp_authenticate_user` only fires after WordPress successfully loads a user from `wp_users`. Archived users are not in `wp_users`, so the hook never receives a `WP_User` object for them — the check is a permanent no-op.

## Section 3: Archived Users Admin View

### Why
Admins currently have no UI way to see archived (soft-deleted) users. WP-CLI is the only option. The `modify_deleted_user_actions()` method was a failed attempt at this.

### Where
New section added to the existing Settings page (`admin-settings.php`) below the Recent Deletions log. Heading: **"Archived Users"**.

### Table columns
| Column | Source |
|--------|--------|
| Original Email | `original_email` |
| Deleted On | `deletion_date` |
| Permanent Removal | `scheduled_deletion_date` |
| Retention | `retention_years` years |

### Behaviour
- Paginates at 20 rows per page using `$_GET['archived_paged']`.
- Shows "No archived users." if the archive table is empty.
- Reads from `wp_user_self_delete_archive`. No write operations from this view.

### Implementation
- New private method `display_archived_users()` in `User_Self_Delete_Admin`.
- Called from `admin_page()` after `display_deletion_log()`.

## Section 4: Accessibility (Modal)

### PHP — `render_confirmation_modal()`
- Outer `<div>` gets: `role="dialog"`, `aria-modal="true"`, `aria-labelledby="delete-account-modal-title"`.
- `<h3>` gets `id="delete-account-modal-title"`.

### JS — `delete-account.js`

**`showModal()`**
- Sets `aria-expanded="true"` on the trigger button.
- Focus trap: Tab and Shift+Tab cycle only among focusable elements inside the modal (password input, Cancel button, Delete button).

**`hideModal()`**
- Sets `aria-expanded="false"` on the trigger button.
- Returns focus to `#delete-account-trigger`.

Escape key already works (existing `keydown` handler). No additional ARIA attribute needed — Escape is standard behaviour for `role="dialog"`.

No CSS changes required.
